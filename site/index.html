Project Overview

Evolution from a standalone Snake script into an enterprise-grade retro arcade operating system.

Architectural Evolution

Pi Arcade OS evolved from a single-game Raspberry Pi Snake controller into a full-featured, hardware-decoupled multi-game operating system. The platform features an object-oriented ArcadeGame interface, non-blocking audio engine, thread-safe input queueing, 16x2 I2C LCD character display output, atomic JSON save file recovery, live color palette switching, an animated CRT terminal boot sequence, and a 100% hardware-isolated test suite.

Engineering Highlights

Core architectural patterns and technical features engineered into the platform.

🔌

Modular ArcadeGame Interface

Decouples game logic from hardware I/O and display rendering using an abstract base class contract.

📚

Dynamic Game Registry

Central registry pattern managing game metadata, instantiation, menu ordering, and coming-soon previews.

⚡

Thread-Safe Input Queue

Multi-threaded gpiozero button callbacks enqueue actions into queue.Queue to prevent Pygame race conditions.

📟

16x2 I2C LCD Output

Real-time score, pause, game-over, and launcher menu updates output to physical character display at 0x27.

🔊

PCM & Buzzer Audio Engine

Programmatic PCM sound wave synthesis for Pygame mixer and passive GPIO buzzer PWM frequencies across 30 sound events.

💾

Crash-Resilient Save System

Atomic temporary file writes and os.replace prevent zero-byte corruptions during sudden power cuts.

🎨

Settings & Theme Engine

Live RGB theme palette switching (Slate Dark, Cyberpunk Gold, Retro Monokai, Neon Synthwave) and multi-channel volume sliders.

📊

Diagnostics & 76+ Unit Tests

Command-line --diagnostics report generator and 100% hardware-isolated test suite running headlessly in CI.

🐍

Python 3.9–3.13 Compatibility

Strict type annotation compatibility validated across Python 3.9, 3.10, 3.11, 3.12, and 3.13 runtimes.

Engineering Challenges Solved

Technical hurdles overcome during embedded arcade platform development.

1. BCM vs. Physical Pin Mapping

Eliminated wiring confusion by mapping software BCM GPIO numbers to exact Raspberry Pi 5 physical header pins.

2. Tactile Button Contact Debouncing

Enforced software contact debouncing (bounce_time=0.05) to eliminate noisy duplicate inputs from tactile switches.

3. Multi-Threaded Input Race Conditions

Prevented Pygame event loop thread crashes by pushing background GPIO button callbacks to a thread-safe queue.Queue.

4. I2C LCD Display Bus Contention

Wrapped physical I2C display calls in try-except isolation guards to ensure display errors never crash game loop execution.

5. Cross-Platform Environment Fallbacks

Engineered graceful degradation allowing the OS to run seamlessly in keyboard-only mode on macOS or headless CI servers.

6. Tetris Escape vs. Pause Input Routing

Resolved control ambiguity by routing pygame.K_ESCAPE exclusively to menu return and pygame.K_p to pause/resume.
